# 3.1 用户管理（6接口）

| 序号 | 接口 | 方法 | 功能 | 技术点 |
| :---: | --- | :---: | --- | --- |
| 1 | `/admin/user/list` | GET | 用户列表 | 分页、多条件模糊/精确查询 |
| 2 | `/admin/user/info` | GET | 用户详情 | 关联查询角色ID列表 |
| 3 | `/admin/user/save` | POST | 保存用户（新增） | 字段校验、默认密码自动填充 |
| 4 | `/admin/user/delete` | DELETE | 删除用户 | 批量删除、逻辑/物理删除 |
| 5 | `/admin/user/update` | PUT | 修改用户 | 密码非空更新规则、全量更新角色 |
| 6 | `/admin/user/status` | GET | 修改用户状态 | 状态码枚举控制（0-禁用 1-启用） |

---

### 接口明细补充
#### 1. 用户列表（`/admin/user/list`）
- **权限**：仅超级管理员
- **查询参数**：`page`（页码）、`limit`（每页数量）、`username`（模糊）、`mobile`（精确）、`status`（枚举）

#### 2. 保存用户（`/admin/user/save`）
- **特殊逻辑**：密码为空时自动赋值默认密码并加密
- **必填项**：`username`（4-20位）、`mobile`（11位）

#### 3. 修改用户状态（`/admin/user/status`）
- **入参**：`userId`（用户ID）、`status`（0-禁用 1-启用）
- **操作**：直接切换账号可用状态

# 3.2 入校审批模块（7接口）
| 序号 | 接口 | 方法 | 功能 | 技术点 |
| :---: | --- | :---: | --- | --- |
| 1 | `/admin/application/list` | GET | 入校申请列表 | 分页、多条件筛选（姓名/手机号/状态/时间范围） |
| 2 | `/admin/application/detail/{id}` | GET | 入校申请详情 | 路径参数ID、关联审批记录/二维码信息 |
| 3 | `/admin/application/approve/{id}` | GET | 入校申请审批通过 | 路径参数ID、自动生成编号与二维码 |
| 4 | `/admin/application/reject/{id}` | PUT | 入校申请审批拒绝 | 必填拒绝原因、状态不可逆控制 |
| 5 | `/admin/application/batch-approve` | PUT | 批量审批通过 | 批量ID处理、统一生成入校记录 |
| 6 | `/admin/application/batch-delete` | DELETE | 批量删除入校申请 | 权限校验、仅可删除未审批/已取消状态 |
| 7 | `/admin/application/pending/count` | GET | 待审批申请数量统计 | 轻量接口、用于前端Badge小红点展示 |

---

## 接口明细补充
### 1. 入校申请列表（`/admin/application/list`）
- **请求参数（Query）**
  | 参数名 | 类型 | 说明 | 是否必填 |
  |--------|------|------|----------|
  | pageNum | integer | 页码，默认1 | 可选 |
  | pageSize | integer | 每页条数，默认20 | 可选 |
  | realName | string | 访客姓名，模糊查询 | 可选 |
  | phone | string | 访客手机号，模糊查询 | 可选 |
  | status | integer | 申请状态（0-待审批 1-已通过 2-已拒绝 3-已取消 4-已预约 5-已完成） | 可选 |
  | startDate | string | 预约开始日期，格式`yyyy-MM-dd` | 可选 |
  | endDate | string | 预约结束日期，格式`yyyy-MM-dd` | 可选 |

### 2. 入校申请详情（`/admin/application/detail/{id}`）
- **请求参数**
  - Path参数：`id`（integer，申请ID，必需）
  - Header参数：`Authorization`（string，可选，格式`Bearer {token}`）
- **响应状态码**：200（成功）、400（请求有误）、401（未认证）

### 3. 入校申请审批通过（`/admin/application/approve/{id}`）
- **核心逻辑**：审批通过后自动生成唯一入校编号与二维码，更新申请状态为「已通过」
- **请求参数**
  - Path参数：`id`（integer，申请ID，必需）
  - Header参数：`Authorization`（string，可选）
- **响应示例**
```json
{
  "code": 200,
  "message": "审批通过",
  "data": {}
}
```

### 4. 入校申请审批拒绝（`/admin/application/reject/{id}`）
- **核心逻辑**：必须填写拒绝原因，状态更新为「已拒绝」
- **请求参数**
  - Path参数：`id`（integer，申请ID，必需）
  - Body参数（application/json）：`reason`（string，拒绝原因，必需）
- **请求示例**
```json
{
  "reason": "入校事由不符合规定"
}
```

### 5. 批量审批通过（`/admin/application/batch-approve`）
- **核心逻辑**：一次性处理多个待审批申请，批量生成入校记录与二维码
- **请求参数**
  - Query参数：`ids`（string，申请ID列表，可选，示例`[1,2]`）、`remark`（string，批量审批意见，可选）
  - Header参数：`Authorization`（string，可选）
  - Body参数（application/json）：`ids`（array[integer]，申请ID列表，必需）、`remark`（string，审批意见，必需）
- **请求示例**
```json
{
  "ids": [1, 2],
  "remark": "批量审批通过"
}
```

### 6. 批量删除入校申请（`/admin/application/batch-delete`）
- **权限限制**：仅可删除「未审批」「已取消」状态的申请，已通过/拒绝/完成状态不可删除
- **请求参数**
  - Header参数：`Authorization`（string，可选）
  - Body参数（application/json）：`ids`（array[integer]，申请ID列表，必需）
- **响应状态码**：200（成功）、400（部分申请无法删除）、401（未登录）

### 7. 待审批申请数量统计（`/admin/application/pending/count`）
- **核心用途**：获取待审批申请总数，适配前端导航栏Badge小红点展示
- **请求参数**：Header参数`Authorization`（string，可选）
- **响应示例**
```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "pendingCount": 12,
    "requestId": "uuid-xxx"
  }
}
```

---

## 公共规范
1.  所有接口均需携带`Authorization`请求头（格式`Bearer {token}`）完成身份鉴权；
2.  状态码`status`枚举统一：0-待审批、1-已通过、2-已拒绝、3-已取消、4-已预约、5-已完成；
3.  批量操作接口（批量审批/删除）均支持多ID批量处理，提升操作效率。
